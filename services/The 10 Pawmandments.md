# The 10 Pawmandments

**I. Thou shalt git pull before writing code.**  
Lest thou awaken the ancient beast known as *Merge Conflict*.

**II. Thou shalt test locally before pushing.**  
For *"it works on my machine"* is not recognized by Production.

**III. Thou shalt update environment variables on the VPS.**  
Production cannot read thy mind when new parameters are added.

**IV. Thou shalt use `workflow_dispatch` for deployments.**  
For automatic workflows yearn only to consume build minutes and developer patience.

**V. Thou shalt not push directly to `main`.**  
The CI pipeline has enough trust issues already.

**VI. Thou shalt write commit messages worthy of remembrance.**  
`fix`, `fixed`, and `final-final-v2` are not historical records.

**VII. Thou shalt not execute major changes in isolation.**  
Plausible deniability expires the moment the client starts typing in ALL CAPS.

**VIII. Thou shalt back up the database before running migrations.**  
*"Surely nothing will happen"* are the last words of many developers.

**IX. Thou shalt explain every block of code upon summoning.**  
*"The AI wrote it"* shall not be accepted as a defense.

**X. Thou shalt not debug in Production.**  
The users are not thy QA team.

---

### Engineering Creed

> *"With great repository access comes great responsibility."*  
> *"Whosoever holds the production credentials, if worthy, shall deploy."*  
> *"The client doesn't need heroes. They need a team."*  
> *"Deploy together. Roll back together. That's what makes us Avengers."*
